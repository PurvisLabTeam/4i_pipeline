4i Pipeline Guide

How to take a 4i experiment from stitched ND2 images to per-cell data, an AnnData file and PHATE plots, using the notebooks in the 4i_pipeline repository on a lab Windows workstation.

04align

05mask debris

Dashed boxes are only needed sometimes: 03 when an automatic alignment is wrong, 05 when a well has debris or artifacts to exclude.

Part 1 · once per computer

Install the pipeline

Skip this part if the workstation already has the repository and you only need to update it (see Updating).

  1. Install Git and uv

    Install Git for Windows with the default options. Then open PowerShell and install uv, the tool that creates the Python environment:

    powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

    Close PowerShell and open a new one so both commands are found.

  2. Download the repository

    Clone it into your own folder on the workstation, not onto Z: (code and environments run much slower from the network drive). You need access to the PurvisLabTeam organization on GitHub.

    cd $HOME
git clone https://github.com/PurvisLabTeam/4i_pipeline.git
cd 4i_pipeline

  3. Create the environment

    This installs Python 3.12 and every package the notebooks use (Cellpose-SAM with the GPU build of PyTorch, napari, scanpy, PHATE, delve). It takes a few minutes the first time.

    uv sync
uv run nbstripout --install

    The second command makes git leave notebook outputs out of commits, so your runs never show up as code changes.

  4. Open the notebooks in VS Code

    1. Install the Python and Jupyter extensions (both by Microsoft).
    2. File → Open Folder… and choose the 4i_pipeline folder (the folder itself, not a single notebook).
    3. Open any notebook, click Select Kernel (top right) → Python Environments → .venv. VS Code remembers this per notebook.
    GPU driver

    Segmentation needs an NVIDIA driver recent enough for CUDA 13 (driver 580 or newer). Run nvidia-smi in PowerShell to see the driver version and GPU.

Part 2 · once per experiment

Prepare the experiment folder

Everything for one experiment lives in one folder on Z:. You provide the raw data and the info file; the notebooks create the rest.

Z:\Name\Experiment folder\
  experiment.json         written by setup_experiment
  info_exp.csv            you provide: channel names per round
  data\                   you provide: stitched .nd2 files
    Round_R0_DNA_pRB_RB_CDK2\
      WellB02_ChannelDAPI_4i,AF488,AF568,AF647_Seq0036.nd2
      WellB03_Channel...nd2
    Round_R1_DNA_CDK4_E2F1_CyclinA2\
      ...
  output_df\  output_images\  segmented\  aligned_tiffs\  masks\  cell_data\   created by 00–06
  fullest_df.csv  standard_adata.h5ad  standard_adata_sub.h5ad                  created by 07

  1. Put the stitched ND2 files in data\

    • One subfolder per round, named Round_<round>_…. Round names must be unique (no Round_00_bad next to Round_00_good).
    • Keep the standard Elements file names starting Well<well>_Channel, e.g. WellB02_Channel…. Tile files (Well…_Point…) can stay in the folder; they are ignored.
    • Stitched images may differ slightly in size between rounds; 00 trims them to a common size.

  2. Write info_exp.csv

    One row per round. The first column is the round name used in the folder names; the other column headers are the optical configuration (OC) names from Elements; each cell says what that channel stained in that round. Leave a cell empty if an OC wasn't used in that round. Every round needs a DNA channel, which is used for alignment.

    myRoundDAPI_4iAF488AF568AF647
    R0DNApRBRBCDK2
    R1DNACDK4E2F1CyclinA2
    R4DNACDT1

    The per-cell columns are named from this file, e.g. R0_pRB_nuc_mean, R1_CDK4_ring_mean.

Part 3 · once per experiment

Describe the experiment with setup_experiment

This form writes experiment.json: the wells, each well's treatment, dose and time, and the derived features for notebook 07. Every pipeline notebook reads it, so there are no paths or well lists to edit in the notebooks.

  1. Load the folder

    Open setup_experiment.ipynb, put the experiment folder in the cell and run it:

    folder = r'Z:\Name\Experiment folder'

    Or leave it empty, type the folder in the form and click Load folder. Messages (including "Folder not found") appear at the bottom of the form, above the Save button.

    If the raw data or the info file are somewhere else, fill in data folder / info file (a full path, or one relative to the experiment folder).

  2. Fill in the experiment details

    Experiment key is a short unique ID such as CM_exp1.3_20260310 (letters, numbers, _ - ., no spaces). Name, cell type, passage, date and notes are for people reading the config later.

  3. Choose wells and conditions on the plate

    ·No ND2 files for this well
    Has data, not included
    123Included; colour and number are the sample_ID
    ✓Selected for a condition
    1. In Include / exclude wells mode, click wells to add or remove them (all wells with data start included).
    2. Switch to Select wells for a condition, click the wells that got the same treatment, fill in treatment, dose, treatment_time and click Apply to selected wells. Repeat for each condition.
    3. Need another column, such as replicate or cell_line? Type it in Extra columns. Tick it under Columns that define a condition only if it should split samples (a replicate number shouldn't).

    Wells with the same condition get the same sample_ID automatically, numbered in plate order. The table under step 5 shows each sample_ID, its condition and its wells.

  4. Or import the plate layout from a CSV

    One row per well; only well is required (B2 and B02 both work). Add sample_ID only if you want to keep numbering from earlier experiments; otherwise leave it out.

    well,treatment,dose,treatment_time
B02,control,0,96h
B03,abema_fulv,100nM,96h
C02,control,0,96h

    Export CSV template writes a CSV listing the wells with data, ready to fill in with Excel; put its name in the CSV box and click Import CSV when done. You can still adjust wells on the plate afterwards.

  5. Check the derived features

    One per line as name = formula, using the per-cell column names. The form suggests pRB_RB_ratio and total_area_DNA when those channels exist and lists the available columns.

    pRB_RB_ratio = R0_pRB_nuc_mean / R0_RB_nuc_mean
total_area_DNA = R0_DNA_nuc_mean * nuc_area

  6. Save

    Click Save experiment.json. The form refuses to save if a well is listed twice or has no ND2 files, and warns about other problems (for example one sample_ID covering two conditions). It keeps the previous version as experiment.json.bak and prints the line for the next part:

    CONFIG = r'Z:\Name\Experiment folder\experiment.json'
Part 4 · each experiment

Run the notebooks

In every notebook, replace the placeholder CONFIG = r'Z:\PATH\TO\EXPERIMENT\experiment.json' at the top with your line from the form, then run the cells from the top. Each notebook prints which experiment it loaded; check it before continuing. Run them in order: each one reads the previous one's output.

00

Preprocess data

Does
Builds a table of every round and channel for each well and saves the DNA image of each round, trimmed to a common size, for segmentation. It prints “Data preparation passed tests” when every round has exactly one DNA channel.
You set
Nothing besides CONFIG.
Writes
output_df\df_<well>.pkl, output_images\<well>\
01

Cellpose segmentation

GPU
Does
Segments nuclei in each round's DNA image with Cellpose-SAM. It stops right away with an error if PyTorch can't see the GPU.
You set
selected_diameter (default 30 pixels). SAM handles a range of sizes, so change it only if nuclei come out clearly too large or too small.
Writes
segmented\<well>\labels_<well>_round_000.tif, …

The first run on a computer downloads the SAM model (about 1 GB). Run nvidia-smi in PowerShell while it works to see GPU use. If it fails with CUDA out of memory, add batch_size=4 (or 2) to the model.eval(...) call.

02

Find transforms

Does
Registers every round's segmentation to the first round (rigid: shift and rotation) and saves the transforms.
You set
downscale_factor (1 = full size; 2 if it runs out of memory on very large images).
Writes
output_df\tmat_<well>.pkl

The last cells (“Optional - test transformations”) open napari to inspect the alignment of the first well; skip them unless you want to look.

03

Fix an alignment by hand

only if needed
Does
Opens two rounds of one well in napari with the Affinder plugin so you can set the transform by clicking matching points, then replaces that round's transform.
You set
myWell (e.g. 'D03'), myRound (the round to fix, as named in the folders) and anchor_round_selected. In Affinder choose the reference image, the image to transform and “similarity”.
Writes
Updates output_df\tmat_<well>.pkl; rerun 04 for that well afterwards.
04

Align all channels

Does
Applies the transforms to every channel of every round and saves one aligned TIFF per channel.
You set
Nothing besides CONFIG.
Writes
aligned_tiffs\<well>\Round_R0_wellB02_pRB.tif, …
05

Mask debris and artifacts

only if needed
Does
Opens a well's aligned images in napari. Draw shapes on the mask layer over regions to exclude; use Choose channel to look through the channels.
You set
selected_well (one well at a time) and use_existing (True adds to a saved mask).
Writes
masks\mask_<well>.pkl. Click Save Mask before closing napari.
06

Calculate cell properties

Does
Measures every nucleus and a cytoplasmic ring around it in every channel: area, shape, mean intensities, total nuclear protein and nuclear/cytoplasm ratios. Cells touching the image border or without DNA signal are dropped, and the mask is recorded per cell. It stops if two rounds have the same round/signal name.
You set
label_round (which round's segmentation defines the cells; default 0).
Writes
cell_data\cell_data_<well>_df.csv and .pkl
07

AnnData conversion

Does
Combines all wells with their metadata from the config, adds the derived features, optionally labels cells pRB high/low, z-scores the features and saves an AnnData file plus a 2,000-cells-per-sample subsample made with kernel herding.
You set
  • After the histogram, pick a cutoff and set THRESHOLD_Z in the threshold cell.
  • Run either the ONE threshold cell (pRB low/high) or the TWO threshold cell (low/middle/high), not both.
  • The histogram uses the control sample by default (THRESHOLD_SAMPLE_ID).
Writes
fullest_df.csv, standard_adata.h5ad, standard_adata_sub.h5ad in the experiment folder

A derived feature whose channels aren't in this experiment is skipped with a “SKIPPED” message; that's expected, not an error.

08

PHATE plotting

Does
Keeps the features you list, ranks them with delve's Laplacian score, computes a 3D PHATE embedding and exports plots coloured by each feature to PowerPoint.
You set
features_to_keep (use your panel's column names), selected_sample_ids, and the PHATE settings count_list (nearest neighbours) and index_ranges (how many top-ranked features to use).
Writes
standard_adata_sub_filtered…h5ad, phate_plots\ and .pptx files in the experiment folder
Comparing with experiments segmented before Cellpose-SAM

SAM draws tighter nuclear outlines than the older Cellpose model. On the same cells, nuclear areas come out about 20% smaller, totals (mean × area) about 14% lower, and ring means slightly higher. Cell counts and nuclear means agree closely. Within an experiment everything is consistent, but don't pool areas, totals or nuclear/cytoplasm ratios with pre-SAM experiments without accounting for this.

Part 5 · reference

Updating and troubleshooting

  1. Get the latest version

    In PowerShell, in the 4i_pipeline folder:

    git pull
uv sync

    Restart the notebook kernel afterwards (the ↻ button in VS Code) so it picks up new packages.

You seeWhat to do
No experiment config at …The CONFIG line still has the placeholder or a wrong path. Paste the line the setup form printed.
All wells on the setup plate are greyNo folder is loaded, or no ND2 files were found. Check the message at the bottom of the form, the folder path, and that data\ holds Round_… folders with Well…_Channel…nd2 files.
No GPU available to PyTorch in 01Run uv sync in the repository folder and restart the kernel. If it persists, check nvidia-smi and update the NVIDIA driver.
CUDA out of memory in 01Add batch_size=4 (or 2) to model.eval(...).
Kernel list doesn't show .venvOpen the repository folder (not a single file) in VS Code, or choose Enter interpreter path and pick .venv\Scripts\python.exe.
Data preparation passed tests is missing in 00A round has no DNA channel or more than one. Check info_exp.csv.
Duplicate round/signal names in 06Two rounds in info_exp.csv use the same round name and signal. Make them unique and rerun from 00.
Notebook outputs show up in git diffRun uv run nbstripout --install once in this copy of the repository.
